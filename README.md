# طرح‌باف (knit) — تصویر به فلاپی بافندگی جاکوارد Karl Mayer

جایگزین برنامهٔ DOS تبدیل تصویر به فلاپیِ دستگاه جاکوارد راشل کارل مایر (نرم‌افزار TDC ~۱۹۹۱).
v7: **یک فایل exe مستقل** — TIF → IMG، بدون هیچ فایل جانبی، بدون قالب جاسازی‌شده.
LAENGE و اثرانگشت p87 کاملاً از فرمول‌های مهندسی‌معکوس‌شده ساخته می‌شوند
(اثبات پذیرش توسط خود PC-CONV: 2026-10-26، exp/laenge_model.py).

## استفاده
1. «بازکردن تصویر…» — نام/تاریخ خودکار.
2. «ساخت فایل فلاپی» — IMG کنار تصویر ذخیره می‌شود (طرح خیلی بلند: دو دیسک خودکار).
«قالب از فایل» فقط برای مقالهٔ دیگری است که خروجی‌اش را بایت‌به‌بایت با PC-CONV بخواهید
(LAENGE واقعی همان مقاله را از یک فلاپی کارکرده برمی‌دارد)؛ برای مقالهٔ 135HQ لازم نیست.

## راهنمای استفاده برای اپراتور (نسخهٔ v7.1)

### کار روزمره — فقط سه قدم:
1. **«بازکردن تصویر…»** — فایل تصویر (TIF طرح، یا JPG/PNG/BMP عکس) را انتخاب کنید.
2. **نام طرح** — خودکار از نام فایل پر می‌شود؛ اگر بخواهید داخل فلاپی اسم دیگری ثبت شود عوضش کنید.
3. **«ساخت فایل فلاپی»** — فایل IMG کنار همان تصویر ذخیره می‌شود (همان نام، پسوند img).
   طرح‌های خیلی بلند خودکار دو فایل می‌شوند (دیسک ۱ و دیسک ۲).
بعد فایل IMG را با WinImage/RawWrite روی فلاپی بنویسید و به دستگاه بدهید.

### بقیهٔ گزینه‌ها چیستند؟ (دکمهٔ «تنظیمات پیشرفته ▸»)
این‌ها برای کار معمولی لازم نیستند و پیش‌فرض‌شان درست است:
- **تاریخ**: خودکار از ساعت ویندوز؛ در هدر فایل ثبت می‌شود.
- **آستانهٔ سیاه/سفید**: فقط برای عکس — تعیین می‌کند کدام پیکسل‌ها بافته شوند. برای TIF طرح بی‌اثر.
- **پیکسل تیرهٔ تصویر = بافته‌شده**: همیشه روشن بماند (برای TIF طرح).
- **مقیاس نرم/تیز**: فقط وقتی اندازهٔ تصویر با عرض مقاله نخواند عمل می‌کند.
  نرم برای عکس، تیز برای طرح خطی. اگر TIF را همان‌طور که ساخته شده بدهید، بی‌اثر است.
- **قالب از فایل**: فقط وقتی مقاله یا تنظیمات ماشین عوض شود (روز مبادا).
  یک فلاپی کارکردهٔ همان مقاله را می‌خواند و تنظیماتش را برمی‌دارد.

### برای برنامه‌نویس‌ها: بیلد از سورس
این ریپو فقط کد است (بدون هیچ دادهٔ کارل مایر). بیلد عمومی یک‌بار «قالب از فایل» می‌خواهد.
برای بیلد مستقل مثل نسخهٔ آماده: `python3 make_machine_cfg.py reference_floppy.img`
(فلاپی مرجع سیستمِ لایسنس‌دار خودتان) → machine_cfg.h → بعد بیلد. جزئیات در هدر خود اسکریپت.
```
x86_64-w64-mingw32-gcc -O2 -municode -mwindows -static -finput-charset=UTF-8 \
    -o knitter.exe main.c tdc_format.c -lgdiplus -lcomdlg32 -lcomctl32 -lgdi32
```

### نکته‌های مهم
- قبل از استفادهٔ واقعی، یک خروجی را یک‌بار روی دستگاه باف کنید و نتیجه را ببینید.
- اگر برنامه فایل نساخت یا خطا داد، پیام پایین پنجره توضیح می‌دهد.
- این برنامه جای هیچ‌کدام از فایل‌های دیگر نیست — فقط همین یک exe کافی است.

## فایل‌ها (برای توسعه‌دهنده)
- `knitter.exe` — برنامهٔ ویندوزی v7 (تک‌فایل، بدون وابستگی)
- `main.c` — GUI ویندوزی؛ `tdc_format.c/h` — هستهٔ فرمت (شامل `tdc_gen_laenge`)
- `machine_cfg.h` — ثابت‌های ماشین (پارامتر static + تریلر کپی‌رایت) از فلاپی مرجع اپراتور
- `FORMAT.md` — مستند کامل فرمت + فرمول‌ها
- `exp/laenge_model.py` — مستند ریاضی LAENGE؛ `exp/battery_*.sh` — باتری‌های آزمایش DOSBox

## فرمول‌های کشف‌شده
- p87 (اثرانگشت) = 3·(ord(name[2]) + (dd−1) mod 10 − 26) mod 256
- len(LAENGE) = (180 + h·((rb mod 64)+2)) mod 2048 ،  rb = ⌈w_bits/8⌉ زوج
- S (سکتور) = ⌊(640 + pitch·h)/256⌋ ، pitch = rb+2
- گرید نشانگر: قفل به انتهای فایل؛ sep = [rb−1,−rb] یا ۳بایتی اگر rb≠⌈w/8⌉

## تست
```
gcc -O2 -o test_core test_core.c tdc_format.c
./test_core samples/129hp_image testdata/129hp_image.rows 1648 512 1648   # 0
./test_core samples/2224_2_image testdata/2224_2_image.rows 1016 6120 1015 # 0
python3 test_same.py   # خروجی = مرجع DOS به‌جز تاریخ امروز
```
پذیرش: فلاپی کاملاً سینتتیک (LAENGE مولد) توسط PC-CONV خوانده و TIF بازخوانده
پیکسل‌به‌پیکسل با منبع یکی بود (dosrun, 2026-10-26).

x86_64-w64-mingw32-gcc -O2 -municode -mwindows -static -finput-charset=UTF-8 \
