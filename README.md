# طرح‌باف (knit) — تصویر به فلاپی بافندگی جاکوارد Karl Mayer

جایگزین ویندوزیِ برنامهٔ DOS تبدیل تصویر به فلاپیِ دستگاه جاکوارد راشل کارل مایر (نرم‌افزار TDC ~۱۹۹۱).
فرمت فلاپی کاملاً مهندسی معکوس شده و بازسازِ این ریپو روی نمونه‌های واقعی **بایت‌به‌بایت** تأیید شده
(۰ بایت اختلاف — جزئیات در `FORMAT.md`).

## فایل‌ها
- `knitter.exe` — برنامهٔ ویندوزی (تک‌فایل ~۱۷۰KB، بدون هیچ وابستگی؛ ویندوز ۷ به بعد — روی XP هم باید اجرا شود)
- `main.c` — GUI ویندوزی (Win32 + GDI+)، `tdc_format.c/h` — هستهٔ مستقل فرمت
- `test_core.c` — تست بایت‌دقیق هسته؛ `make_vectors.py` — سازندهٔ ورودی تست از TIF نمونه‌ها
- `validate.py` + `karlmayer_tdc.py` — مرجع پایتونی (مهندسی معکوس اولیه)
- `samples/` — نمونه‌های کاربر (دیسک‌ها + TIF)، `testdata/` — ورودی تست ساخته‌شده
- `FORMAT.md` — مستند کامل فرمت

## استفاده (گردش کار)
1. **فلاپی مرجع**: یکی از فلاپی‌های کارکردهٔ همان مقاله را به‌صورت فایل IMG باز کنید
   (یا مستقیم از درایو A: بخوانید). برنامه از آن «قالب» را می‌گیرد: عرض ماشین،
   بلوک LAENGE، تریلر کپی‌رایت و فیلد اثرانگشت پارامتر — چیزهایی که طرح‌مستقل‌اند
   و بدون فهم کامل، از قالب کپی می‌شوند.
2. **تصویر** را باز کنید. نام طرح/تاریخ/تعداد ردیف خودکار پیشنهاد می‌شود.
3. آستانهٔ سیاه/سفید و مقیاس (نرم برای عکس / تیز برای طرح خطی) را تنظیم کنید؛
   پیش‌نمایش همان چیزی است که بافته می‌شود (پیکسل تیرهٔ تصویر = بافته).
4. **ذخیرهٔ فایل(های) فلاپی…** → فایل IMG (اگر طرح بلند باشد خودکار دو دیسک
   `<نام>.img` و `<نام>-disk2.img`) — یا **نوشتن روی فلاپی A:** مستقیم روی فلاپی خام.

ردیف‌ها از پایین به بالا نوشته می‌شوند (مطابق TDC)؛ دیسک ۱ = ردیف‌های پایینی، دیسک ۲ = بالایی.

## بیلد (روی این سیستم)
```
x86_64-w64-mingw32-gcc -O2 -municode -mwindows -static -finput-charset=UTF-8 \
    -o knitter.exe main.c tdc_format.c -lgdiplus -lcomdlg32 -lcomctl32 -lgdi32
```
تست بایت‌دقیق (native):
```
gcc -O2 -o test_core test_core.c tdc_format.c
./make_vectors.py
./test_core samples/129hp_image    testdata/129hp_image.rows    1648 512 1648   # → 0 = PASS
./test_core samples/2224_2_image   testdata/2224_2_image.rows   1016 6120 1015  # → 0 = PASS
```
تست exe ویندوزی زیر wine: `wine64 knitter.exe --selftest <img> <rows.bin> <wbits> <h> <wpx>` → کد خروج ۰.

## تأیید انجام‌شده
- بازسازی کامل `129hp_image` از روی TIF آن: **۰ بایت اختلاف**
- بازسازی کامل `2224_2_image` (گام ۱۳۰، عرض ۱۰۱۵/۱۰۱۶): **۰ بایت اختلاف**
- هر دو تست داخل خودِ `knitter.exe` (زیر wine) هم PASS شد.
- `bedspread` (دودیسکی) به‌دلیل تاریخچهٔ چندبارذخیره روی خود دیسک‌ها قابل انطباق بایت‌دقیق نیست؛
  ولی همهٔ فیلدهای دودیسکی (۲۴..۲۹ پارامتر، تقسیم ردیف‌ها) مستقیم از همان نمونه خوانده و پیاده شده.

## محدودیت‌ها / نکته‌ها
- ستون(های) حاشیه (وقتی عرض بسته‌بندی > عرض واقعی) سفید نوشته می‌شود — مطابق نمونه‌ها.
- فیلد بایت ۸۸ پارامتر (0x5D/0x48/0x7E در نمونه‌ها) رمزگشایی نشد → از قالب کپی می‌شود.
- اگر مقاله/ماشین عوض شود، فلاپی مرجع تازه لازم است (LAENGE وابستهٔ مقاله است).
- «نوشتن روی فلاپی A:» روی بعضی ویندوزها نیاز به دسترسی مستقیم دیسک دارد؛ در آن صورت
  فایل IMG را با WinImage/RawWrite بنویسید.
- **قبل از استفاده در تولید**: یک خروجی را حتماً یک‌بار در خود برنامهٔ DOS یا روی دستگاه تست کنید.
